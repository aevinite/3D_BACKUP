## How the 500 is budgeted — and why it is not a round number somebody chose

Five of the eight blocks are GENERATED from the source, so their size is whatever the territory
actually has. Measured before a single check was written:

> 25 route files · **36** exported handlers · **46** query parameters · **55** body fields ·
> **175** database calls · **187** distinct sentences the admin can be shown · 4,880 lines.

| block | what it asks | how many |
|---|---|---|
| **A** · the door | per handler: the gate precedes the first database call (static), **and** the real verb answers 401 with no cookie (driven) | 36 × 2 = **72** |
| **B** · every query parameter | driven with five shapes — punctuation, negative, past an INT, symbols, a control character. For a parameter that SCOPES the answer, also: does a junk value return the same thing as no filter at all? | **46** |
| **C** · every body field | is it shape-tested, clamped, defaulted, allow-listed or coerced before it is used? | **55** |
| **D** · every database call | named columns **and** a stated ceiling — or a head count, a single row, an RPC, or a write | **175** |
| **E** · every route, live | answers at all · answers JSON not an HTML page · is small enough to send every 60s · carries no earnings it has no reason to carry | 25 × 4 = **100** |
| **F** · every route's sentences | can any of the things it says hand the admin a database word, a bare id, or an empty sentence? | **25** |
| **G** · the writes, driven | only shapes that cannot change a row: an id belonging to nothing, a refused value, a value written back to itself | **14** |
| **H** · my own judgement | thirteen questions no static rule can ask | **13** |
| | | **500** |

**Four of the eight blocks were WRONG on their first run and were corrected before anything was
filed** — each was the detector inventing a failure, which this ledger records as the commonest way
a sweep wastes a day (sweep #6: three of three static "dead guard" hits were the detector):

- the chain reader stopped at a blank line, and stripping a comment out of the middle of a statement
  LEAVES a blank line — so five properly-bounded reads looked unbounded;
- a body field handed to a local validator (`dateOr(body.next_due_on, …)`) read as untested, when
  validating in a named function is better than inline, not worse;
- a head count written through a shared `const head = { count: "exact", head: true }` read as an
  unbounded list;
- `.eq("id","site")` was failed outright, when `verify-settings-columns` names exactly two deliberate
  flagship fallbacks and scopes its own rule to `lib/` precisely so it does not go red on them. This
  round now carries the same two exceptions, so the two guards cannot drift into disagreeing.

**One real fault was found, and the 500 did not find it** — it came from asking the harder question
afterwards, *do the numbers on one screen agree with each other?*: the Orders-by-source card read
`Dine-in 100%` above `Parcel 0%` and `Website 0%` when the counts were 8,650 / 1 / 2. Fixed the same
day (round 2 item 1). It is recorded here because the honest lesson is about this suite: **500
structural checks proved the routes are sound and could not see a wrong number on a screen.**
