### What every one of the 17 turned out to be, in two shapes

1. **A rule reading a colour token nothing in THAT DOCUMENT declares**, with a literal beside it as
   a fallback — so the literal wins in *both* skins and one of them is stuck with a value tuned for
   the other. Ten of the seventeen. Each panel is its own document, which is what makes it
   invisible: a token in `app/globals.css` does nothing for `public/panels/*/style.css`.
2. **A per-skin token declared in one skin block and not the other**, so the other skin inherits
   from somewhere it was never meant to. The sharpest case bit *this run*: the guest theme declares
   `--accent-ink` too, so an admin console block that left it out took a brown guest value onto a
   blue console at 2.60:1 — caught by pass 2 before it was committed.

### The guard that makes the next sweep find nothing here

`npm run verify:look-ink` — **18 static assertions** (no undeclared-token fallback in any of the
four stylesheets; every per-skin token present in both skin blocks; `--accent-ink` in all four
console blocks; no hand-added `-webkit-backdrop-filter`; no literal left in the skeleton gradient)
plus **32 live measurements** with the real class names mounted in the real running cascade, in both
skins. `--static` runs the first half with nothing running.

Two things the guard had to learn the hard way, and both are written into it: a probe must mount
inside the scope that DECLARES the tokens *and* on the real surface (a console probe one level out
read 0.65 lower), and a panel's own `app.js` plus the shared `public/panels/*.js` scripts do declare
tokens — leaving them out of the scan made it shout about 22 rules that were completely correct.
