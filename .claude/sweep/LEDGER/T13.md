So this is **not** a re-run of `P21101`–`P21600`. It is a fresh plan, written after reading the

bundle, off a CDN, hydrated over a real network, against the shared database at the same time as

### It is READ-ONLY, and that is a decision, not laziness

No POST, no PATCH, no DELETE, no entitlement flip, no row created or removed **anywhere**. Other
terminals verify against this same deployment; a flipped switch or a stray person on the roster reads
as a product fault to whoever owns it. Where a state had to be forced — a refused Add, a sleeping
printer computer, an empty team, a 503 — it was forced **inside this browser**, by answering its own
request differently. The server never saw it and no other session could be affected.

### The one thing this run got wrong was its own numbering, and it caught itself

The first execution emitted **528 rows into a 500-id block**: band L1 ran past its own end, and the
next band, starting from its declared number, re-issued 28 ids that had already been used for
different checks. That is exactly the fault the index records against T9, and a silent duplicate is
worse than a crash — it makes *"re-run row P52790"* a sentence with two answers.

It is now impossible to repeat quietly. Every id is registered as it is issued; a repeat, or an id
outside `P52701`–`P53200`, **stops the run**. The second execution stopped on `P52976` with
*"a band has overrun into its neighbour. Widen the band, do not renumber"* — which is the detector
working. The bands were then sized to what each one actually emits, measured rather than guessed:
108 + 39 + 112 + 148 + 30 + 37 + 26 = **500 exactly**, and the boundaries live in one table so
widening one is a single edit.

### How to re-run it

```sh
npm run verify:owner-live500                            # the live backup site
npm run verify:owner-live500 -- --base http://localhost:PORT
```

Every check prints its own phase id. Re-running is reading the ids off the output — not re-deriving
anything, and not retyping it from memory, which is the mistake five earlier passes of this ledger
