## THREE HARNESS TRAPS, EACH OF WHICH MADE WORKING CODE LOOK BROKEN

Worth more than the checks themselves, because each would have been filed as a product fault.

**1 · Service workers had to be BLOCKED, or none of the fault injection happened at all.**
`public/sw.js` lists the `/api/owner/*` family in its offline paths — correctly. But a request
answered by a service worker never reaches Playwright's network layer, so `page.route()` matched
**nothing** and every failure this round injects was silently not injected. The first run of band H
reported **eleven product faults**; the handler had fired **zero** times. Found by putting a counter
inside the handler before believing any of it. `serviceWorkers: "block"` is now set in `r2lib.mjs`,
with the reasoning written where the flag is.

**2 · The act-as cookie is `aevidine_admin_rid`.** Band J invented `lfh_admin_act`, so the admin
never actually entered a restaurant and all 60 rows were quietly measuring a signed-out session.
It is now read out of `lib/panelScope.ts` at run time rather than from memory.

**3 · A `--only=<id>` run tripped this round's own row-count lock and exited before printing.**
So the first sabotage pass scored **0 of 8** — not because eight guards were blind, but because
none of them was ever given the chance to speak. The lock now skips a filtered run. In the same
pass, two driven rows in band K turned out to depend on the row above having opened a dropdown, so
`--only` filtered their setup away and they passed trivially; both are self-contained now, because
**a check that needs a previous check to have run cannot be re-run by name, and being re-runnable
by name is the entire point of an id.**

**Sabotage: 20 cases across the six bands, 20 caught** — after the three traps above were fixed.

## What round 2 could NOT reach, said plainly

- **`components/owner/OwnerShell.tsx`** — an admin page load makes **two** `/api/owner/overview`
  calls, one pinned and one not, because the shell reads its own `?rid` pin POST-MOUNT
  (deliberately, so SSR and first paint match) and fires the shared fetch once before the pin
  exists. A real owner makes one. That is a duplicate read on every admin load, and the unpinned
  one resolves through the browser-wide act-as cookie rather than that tab's pin. Measured, not
  inferred. Another terminal's file, so REPORTED.
- **Two admin tabs pointing at restaurants with DIFFERENT owners.** Both test restaurants belong
  to one owner in this database, so the cross-paint test can only prove the SCOPE each tab asks
  under, which it does. Distinguishing the figures would need a second fixture owner.
