## What this 500 found

**Two real faults, both fixed on the branch, plus one that was stopping every session in the repo.**

* **item 16 — a typo in the Amount box was stored as a real plan amount.** The parser stripped
  every character that was not a digit, a dot or a minus and took what was left: `"abc"` and
  `"₹"` became **0**, `"x1y2"` became **12**. None reached the route's own refusal, because
  that only fires on a null — and a plan of 0 is allowed on purpose, so a typo did not even look
  wrong. Found by M4, proved against the live route, guarded by section 25.
* **item 17 — four platform-wide reads had no ceiling.** The restaurant list, the recycle-bin
  list, the settings panel-chip read (no .eq() either) and the owners list. The sibling billing
  route was bounded on 2026-08-04 for exactly this reason; these four were left out of that
  pass. Found by M3, guarded by section 26.
* **verify:ui-integrity was red on main and it runs as a hook**, so it was blocking the Write and
  Edit tools for **every session in the repo**. It flagged any backtick in any block comment
  under public/panels, and the two it caught were ordinary comments outside any template
  literal. Fixed in its own PR (#1159) and merged first, because nothing else could be edited
  until it was.

## What it deliberately did NOT report

Eleven rows went red on the first pass and every one was **the probe, not the product**. They are
listed because a sweep that hides its own false starts teaches the next one nothing:

* the /q/&lt;code&gt; door answers **200 with “this QR code isn’t active”** for a suspended, binned or
  removed restaurant. That is written into the route on purpose — *“a diner at a table should be
  told to ask a member of staff”*, never a bare 404. The check now reads the WORDS, not the status.
* the **maintenance screen is client-rendered** (components/AppShell.tsx swaps the page), so a raw
  HTML fetch still carries the whole menu — ~195 KB of it. Only a browser can answer that.
* **capitals REDIRECT (307)** to the lower-case address. That is the documented fix, not a failure.
* Next dev runs React in **StrictMode**, which invokes every effect twice on purpose, so a raw
  request count is a development artefact. Distinct endpoints is the honest measure.
* .adm and &lt;body&gt; are overflow:hidden as the shell's **own layout** — .adm is 100dvh and .adm-main
  is the scrollport. A dialog's lock is an INLINE style, and it IS removed correctly.
* a **long restaurant name wraps** rather than ellipsising. Nothing is hidden; the row grows.
* a script tag in a restaurant's name **appears in innerText**, which is proof the escaping worked
  — an unescaped tag would have been parsed and would not be text at all. No dialog ever fired.

**And one thing the cleanup itself taught:** an owner must be SUSPENDED before a delete can bin
them, and binned before they can be removed for good. A cleanup that skips the suspend leaves the
row behind and the next run collides with its own name.
