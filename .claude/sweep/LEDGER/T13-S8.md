## ⚠️ THE IDS IN BANDS B, D, E AND F ARE POSITIONAL — AND THAT IS NOW LOCKED

Those four bands hand out ids from a counter in execution order, because three of them generate
rows in loops (eight periods × two scopes; eleven junk range values; five popups). That is fine
for a band that is RUN and dangerous the moment a row is INSERTED in the middle: every id after
it shifts, and "an id means one specific check, forever" stops being true.

**I hit this, and it is why the first sabotage pass looked so bad.** I wrote down ids, then added
two rows mid-band for the item-5 fix, then sabotaged against the old numbers — so ten of eighteen
cases read as "the guard stayed green over a real fault" when the guard had fired correctly on a
number one or two along. Nothing was wrong with the product or the checks; my map was stale.

Each of those four bands now declares `EXPECT_ROWS` and **refuses to run if its own row count
changes**. Insert a row and it exits 2 with the reason, which forces a deliberate choice: append
at the END so existing ids stay put, or renumber on purpose and update this file. Bands A and C
use literal ids and are not exposed to it.

`T13_DUMP_IDS=1 node scripts/sweep/t13/<band>.mjs` prints the id → check mapping.

### Why band B is driven rather than read
`windowFor()`, `prevWindowFor()`, `prevTsWindowFor()`, `heatFrom()` and `rangeKey` decide what
period every figure on this screen covers, and no existing row anywhere names any of them. Since
v6 the payload carries `window: { from, to }`, so the route will simply tell you what it resolved
— for all eleven range values, the eleven junk ones it must answer as "today", and five malformed
custom ranges. That is how item 5 was found.

### Why band C executes the real source
A regex cannot tell you what `hour12(0)` returns. Each helper's source text is lifted out of
`page.tsx` **with TypeScript's own parser** and run. Two hand-rolled lifters got it wrong first —
a regex whose escaping did not survive the quoting, and a brace-matcher that started at the
RETURN TYPE's brace and lifted the signature alone — and both would have "passed" while running
nothing.

### Why band D reads computed styles
This file has silently lost a styling rule at least three times, and every time the rule was right
there in the source: `.hq-table th` compiling to a selector that matched nothing, and two rules
losing the cascade to `globals.css`. Only the browser can say whether a rule reached anything.
