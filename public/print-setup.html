Kitchen printer — the complete setup guide

Everything needed to make kitchen tickets (KOTs) print by themselves — on Windows, a Mac, Linux or a Raspberry Pi (and which devices can never do it) — every step, every setting, and what to do when something goes wrong. Written for someone who has never set up a printer before.

Each starter arrives already pointed at this site — there is nothing to edit. Add ?panel=manager to a link for a counter screen instead of a kitchen one.

1 · The 6-step short version

  1. Plug the thermal printer into the computer and make it that computer's default printer.
  2. Download the starter file for that computer (the two buttons at the top of this page). Mac → print-station-mac.command. Windows → print-station-windows.bat.
  3. Nothing to edit — the download already points at this site and at the kitchen screen. (For a counter screen, use the ?panel=manager link instead.)
  4. Double-click the starter file. A single Chrome window opens, full screen. Log in once — it stays logged in from then on.
  5. Turn it on in the app — in the admin console's 🖨 KOT printing card: switch auto-print ON, and pick which screen prints. If you picked the counter screen, answer Yes, print here on the strip that appears above that computer's Tables screen. (details below)
  6. Test it: send one order. Then minimise that Chrome window and send another. Both tickets must come out. That second one is the whole point.
In simple words: plug the printer in, open one special Chrome window that never falls asleep, flick two switches in the app, and check it still prints when the window is hidden.

2 · Why printing used to stop (worth 60 seconds)

Kitchen tickets used to be printed by the kitchen screen watching for new orders. That only works while that screen is the window you are looking at. The moment it was minimised — or simply covered by any other app on the same computer — the browser put it to sleep and printing stopped completely, with nothing anywhere saying so.

That is fixed at the root now: the order itself leaves a "print me" job on our server. Any screen that is set up to print picks the job up, prints it, and tells the server it is done. If no screen picks it up, the job waits — it can no longer be lost — and after 90 seconds the manager's Tables screen shows a warning with a 🖨 Print here instead button.

What this means for you: the kitchen window can be minimised, covered, or on another desktop, and tickets still print. If the computer is off, the tickets are waiting the moment it comes back on.

The starter files on this page are the second half of the fix: they open Chrome with the specific settings that stop it dozing off behind other windows, and they keep the computer itself awake.

The printer

(e.g. Epson TM-T82X LAN)		₹8,000–12,000 Recommended. No long cable — the printer sits in the kitchen on the same Wi-Fi and the computer can be anywhere. Needs the restaurant's Wi-Fi to be steady in the kitchen.

(Star CloudPRNT, Epson Server Direct Print)		₹15,000–25,000 Needs no computer at all — the printer asks our server for tickets by itself. Not switched on in the app yet — see section 12.

The computer

Any Mac or Windows PC already in the restaurant is fine — it does not need to be fast. It needs three things: it stays switched on during service, it is on the internet, and the printer is plugged into it (or on the same network as it).

Paper

80mm thermal rolls. Keep at least two spare. Thermal paper has no ink — if nothing prints, the roll is either finished or in upside down.

4 · Setting up a Mac macOS

4.1 · Install the printer

Most cheap 80mm printers have no macOS driver of their own. For the POS-80 / ZJ-80 family, the open-source zj-58 driver works and is already installed on the owner's Mac. If you are setting up a fresh Mac, this is the whole recipe (it needs an administrator password):

git clone https://github.com/klirichek/zj-58
cd zj-58 && make
sudo cp rastertozj /usr/libexec/cups/filter/
sudo cp zj80.ppd /Library/Printers/PPDs/Contents/Resources/

Then → System Settings → Printers & Scanners → Add Printer, pick the USB printer, and choose the ZJ-80 driver. Name it something plain like Printer_POS_80.

4.2 · The paper settings that matter

These four are not decoration — each one was worked out against a real roll, and getting one wrong is how you end up with 20 cm of blank paper before every ticket, or a cut through the middle of a line:

lpadmin -p Printer_POS_80 \
  -o PageSize=X70MMY65MM \
  -o CutMedia=EndOfJob \
  -o FeedWhere=AfterJob \
  -o FeedDist=9feed30mm \
  -o OptionCutter=True
PageSize=X70MMY65MM
A short receipt page. Chrome flows a long ticket across several of these seamlessly and never slices a line of text in half.
CutMedia=EndOfJob
Cut once, after the ticket is finished. EndOfPage cuts mid-ticket, because the cut happens before the final paper feed.
FeedWhere / FeedDist
Feed the paper out after the job so the ticket clears the tear bar and you are not pulling the next one out of the machine.
OptionCutter=True
Only if your unit actually has a blade. If it doesn't, leave this out.
Never set a paper size in the app's own print settings. A pinned or landscape-shaped page makes the printer turn the ticket sideways, and a size that doesn't match the roll pushes the whole ticket to the bottom of an imaginary page — that is the 20 cm blank lead-in. The app already prints at the right width (66 mm of ink on 80 mm paper); leave it alone.

4.3 · Make it the default printer

System Settings → Printers & Scanners → Default printer → Printer_POS_80. This matters: the silent-print mode used by the starter file always sends to whatever the default printer is.

4.4 · Stop the Mac sleeping

The starter file does this for you while it is running (it holds the Mac awake and lets go when the window closes). If you would rather set it permanently: System Settings → Lock Screen → set the display and the machine never to sleep on power.

4.5 · Open the print station

Read this first — macOS blocks downloaded scripts. When you double-click the starter, a recent Mac says “print-station-mac.command” Not Opened — Apple could not verify it is free of malware, and offers only Done or Move to Bin. Nothing is wrong with the file: Apple refuses any script downloaded from the web that hasn't been through their paid notarisation. The old “right-click → Open” trick no longer works on macOS Sequoia. Use option A below and the question never comes up.

Option A · Paste one line into Terminal easiest — nothing to download

Open Terminal (⌘Space, type “terminal”, Enter), paste this, press Enter. It is the whole starter in one line, so there is no file for macOS to object to. Change /kitchen to /manager for a counter screen.

caffeinate -dimsu "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --kiosk --kiosk-printing \
  --user-data-dir="$HOME/.aevidine-print-station" \
  --disable-background-timer-throttling \
  --disable-backgrounding-occluded-windows \
  --disable-renderer-backgrounding \
  --no-first-run --no-default-browser-check \
  --autoplay-policy=no-user-gesture-required \
  "https://www.aevinite.shop/kitchen"

Leave that Terminal window open — it is what keeps the Mac awake. Closing the Chrome window (⌘Q) ends it. To have it start by itself at login, see 4.6.

Option B · Use the downloaded starter file

  1. Download print-station-mac.command (button at the top of this page).
  2. Start it THROUGH Terminal, which macOS allows: 
    bash ~/Downloads/print-station-mac.command
    That is the whole fix. Running a script through bash is reading a file, not launching an app, so Gatekeeper has nothing to block.
  3. Prefer to double-click it in future? Then clear the download flag once: 
    xattr -d com.apple.quarantine ~/Downloads/print-station-mac.command
chmod +x ~/Downloads/print-station-mac.command
    After that it double-clicks normally, for ever. (The other route is System Settings → Privacy & Security, scroll to the message naming the file, and press Open Anyway — but the two lines above are quicker and do not need the dialog to still be showing.)
  4. Log in once with the restaurant's kitchen (or manager) username and password. This window keeps its own private Chrome profile, so it stays logged in and your everyday Chrome is untouched.

4.6 · Have it open by itself at login (recommended)

So nobody has to remember after a power cut: System Settings → General → Login Items → press + and pick the print-station-mac.command file. (It must be un-quarantined first — the two lines in step 4 above.)

To finish for the day: press ⌘Q in the Chrome window (or close the Terminal window). The Mac is then free to sleep again.

5 · Setting up a Windows PC Windows 10 / 11

5.1 · Install the printer

Windows handles these printers much more easily than macOS. Plug it in — Windows usually finds it. If not, install the driver from the CD or the maker's site (search the model name, e.g. "XP-80C driver"), then check it appears in Settings → Bluetooth & devices → Printers & scanners.

Print a test page from Windows itself before going any further. If Windows can't print, the app certainly can't.

5.2 · Make it the default printer

Settings → Printers & scanners → click your printer → Set as default.
Also turn OFF "Let Windows manage my default printer" on that same screen — otherwise Windows quietly switches the default to whatever was used last, and tickets go to the wrong printer.

5.3 · Paper size

Printer properties → Preferences → Paper size: pick the 80 mm × receipt option (its exact name varies: 80(72.1)mm × Receipt, 80mm × 297mm, …). Do not choose A4.

5.4 · Open the print station

  1. Download print-station-windows.bat (button at the top of this page).
  2. Edit one line. Right-click → Edit (or open it in Notepad). Change: 
    set "URL=https://3-d-backup.vercel.app/kitchen"
    Save and close. Tip If Windows hid the .bat ending and the file is called print-station-windows.bat.txt, rename it back so it ends in .bat.
  3. Double-click it. Windows may warn that it is a file from the internet — choose More info → Run anyway. One full-screen Chrome opens; the file also tells Windows not to sleep or blank the screen while on mains power.
  4. Log in once. Own Chrome profile, stays logged in, your normal Chrome untouched.
  5. Make it start by itself (recommended). Press Win+R, type shell:startup, press Enter, and drag a shortcut to the .bat file into that folder. From now on the print station opens whenever the PC starts, before anyone has to remember.
To finish for the day: press Alt+F4 in the Chrome window.

5b · Setting up Linux — including a Raspberry Pi Ubuntu · Debian · Raspberry Pi OS

Linux is the cheapest way to run a print station that nobody ever touches: a Raspberry Pi (₹4,000–5,000) screwed to the wall behind the till, the printer in the kitchen on the network, and it starts itself when the power comes back after a cut.

5b.1 · Install the printer (CUPS)

Linux prints through CUPS, which is already installed on Raspberry Pi OS and Ubuntu. Plug the printer in and:

sudo apt update && sudo apt install -y cups printer-driver-escpr
sudo usermod -aG lpadmin $USER      # lets you add printers without being root
lpinfo -v                           # shows the printer's address, e.g. usb://Zjiang/POS-80

Add it, name it plainly, and make it the default:

sudo lpadmin -p POS80 -E -v "usb://Zjiang/POS-80" -m raw
sudo lpoptions -d POS80             # default printer for this machine
echo "hello" | lp -d POS80          # a one-line test print

-m raw is deliberate. An 80mm thermal printer speaks ESC/POS; “raw” means CUPS passes the job through untouched, which is what Chrome's own output needs. If your model has a proper PPD (Epson's escpr driver covers many), use that instead of raw.

5b.2 · A NETWORK printer instead of USB (recommended on a Pi)

lpadmin -p POS80 -E -v socket://192.168.1.50:9100 -m raw

Port 9100 is the standard raw-printing port. Give the printer a fixed address in your router first, or it will move and printing will stop for no visible reason.

5b.3 · Paper settings

lpadmin -p POS80 -o PageSize=Custom.72x200mm -o fit-to-page=false

Same rule as the Mac: never force A4, and never let the app set a page size. If tickets come out with a long blank lead-in, the page size is wrong — nothing else causes that.

5b.4 · The print station

Chrome (or Chromium, which Raspberry Pi OS ships) takes the same flags. Save this as print-station.sh, chmod +x it, and run it:

Or just download print-station-linux.sh from the top of this page — it is the same script, already written, and it finds Chromium or Chrome by itself:

#!/bin/sh
URL="https://www.aevinite.shop/kitchen"          # or /manager for the counter screen
PROFILE="$HOME/.aevidine-print-station"
xset s off; xset -dpms; xset s noblank                # never blank the screen
exec chromium-browser --kiosk --kiosk-printing \
  --user-data-dir="$PROFILE" \
  --disable-background-timer-throttling \
  --disable-backgrounding-occluded-windows \
  --disable-renderer-backgrounding \
  --no-first-run --no-default-browser-check \
  --autoplay-policy=no-user-gesture-required "$URL"

On Ubuntu use google-chrome in place of chromium-browser.

5b.5 · Start it on boot (the part that makes it maintenance-free)

mkdir -p ~/.config/autostart
cat > ~/.config/autostart/print-station.desktop <<EOF
[Desktop Entry]
Type=Application
Name=Aevidine print station
Exec=/home/pi/print-station.sh
X-GNOME-Autostart-enabled=true
EOF
Why a Pi is a good idea: it costs less than a month of a POS subscription, uses 3 watts, has no fan to clog with kitchen grease, and after a power cut it comes back by itself — which is the one thing a Windows PC at the till never does.

6 · The switches inside the app

Auto-print needs three things said yes. They are deliberately separate — one belongs to us, one to the restaurant, one to the individual computer.

#SwitchWhere it livesWho sets it
1Auto-print the KOT when a new order arrives Admin console → the restaurant → 🖨 KOT printingAevidine (us)
2Which screen prints the ticket?
The kitchen screen · The counter (manager) screen · Both — counter is the backup		 Admin console → the restaurant → 🖨 KOT printing, right under switch 1 Aevidine (us), at your word
3“Yes, print here” — once, on that computer Manager panel → Tables → a strip above the floor asks the question by itself Whoever is at that computer
In simple words: we allow it, we pick whether the kitchen screen or the counter screen prints, and then the computer itself is asked once whether it is the one with the printer.
Why the computer is asked at all. The manager panel is also opened on phones. If a phone printed, the ticket would go into a dialog nobody looks at and the kitchen would never get paper. So a screen prints only after somebody has said yes on it — and you say No on every phone, which it then never asks again.
A kitchen screen needs no switch 3. With switches 1 and 2 set to the kitchen, a kitchen screen just prints.

There is also a 🖨 Preview a sample KOT button next to switch 1. Use it to check the paper, the width and the cut before service — it prints a fake ticket and never touches a real order.

7 · Choosing WHICH screen prints

Your situationSet this up
A screen and a printer in (or wired to) the kitchen Switch 2 = The kitchen screen. Open the print station on it with /kitchen. Nothing else needed.
No room for a computer in the kitchen — the printer is at the counter, and that screen is also used for billing Switch 2 = The counter (manager) screen. Open the print station on the counter PC with /manager, then answer Yes, print here on the strip that appears above its Tables screen.
Kitchen screen exists, but you want a safety net Switch 2 = Both — the counter is the backup. The kitchen prints as usual; the counter screen prints anything still unprinted after 30 seconds.
Two kitchens / two printers Open a print station on each. They share one queue, so each ticket comes out once — whichever screen claims it first. (A per-printer split — starters here, mains there — is not built yet.)
You cannot cause double tickets by leaving several screens on. The server hands each ticket to exactly one screen. The only ticket that prints twice is one you ask to reprint, and that one comes out stamped *** Reprint · Duplicate *** so nobody cooks it again.

8 · The test that actually matters

  1. Send a real order from the waiter tablet (or the guest menu) to a test table. A ticket should come out within a few seconds.
  2. Now minimise the print-station window — or better, open any other app full screen on top of it. This is exactly what used to kill printing.
  3. Send a second order. A ticket must come out while the window is still hidden. This is the test. If this one prints, you are done.
  4. Close the print station completely and send a third order. Nothing prints — correct. Now open the print station again: the ticket you missed prints straight away. Nothing was lost.
  5. Cancel your test orders so they don't reach a real bill (manager panel → the table → cancel).
In simple words: print one, hide the window and print another, then close everything and prove the missed ticket comes out when you re-open. That covers every way it used to fail.

9 · Every setting in the starter file, explained

You do not need to understand these to use it — but nothing here is magic, so here is exactly what each line does and which problem it removes.

SettingIn plain words
--kioskFull screen, no address bar, no tabs. Nobody can wander off to another website on the printing computer.
--kiosk-printingPrint with no dialog. Without it, every ticket waits for someone to click "Print".
--disable-background-timer-throttlingChrome slows down a window that isn't in front. This stops it.
--disable-backgrounding-occluded-windowsThe important one. Chrome treats a window that another window covers as if it were closed. This is why "opening another app killed printing", and this setting is what fixes it.
--disable-renderer-backgroundingSame idea, one layer deeper: don't put the page itself to sleep.
--disable-features=CalculateNativeWinOcclusionThe Windows version of the covered-window problem.
--user-data-dir=…Its own private Chrome profile. It stays logged in, and your everyday browsing, bookmarks and logins are completely separate.
--no-first-run --no-default-browser-checkSkip the "make Chrome your default browser?" questions, which would otherwise sit on the screen waiting for an answer.
--autoplay-policy=no-user-gesture-requiredLets the new-order chime sound without someone tapping the screen first.
caffeinate (Mac) / powercfg (Windows)Keep the computer awake. A sleeping computer prints nothing, and this is the most common cause of "it stopped overnight".

11 · The daily routine for staff

Opening

  • Switch the computer on. If the starter file is in Startup (Windows), the print station opens by itself — otherwise double-click it.
  • Check the paper roll. Press 🖨 Preview a sample KOT once if you want to be sure.
  • Leave the window alone. It is fine if other apps sit on top of it.

During service

  • Paper out, jam, or half a ticket → tap 🖨❗ on the kitchen screen and pick what happened. The manager is told immediately.
  • Need a ticket again → the 🖨 button on that ticket. It comes out marked as a duplicate, on purpose.

Closing

  • Close the print-station window (⌘Q / Alt+F4). Nothing is lost if an order arrives after that — its ticket prints when you open again.
